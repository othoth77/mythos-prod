## gh-issue-100 — Claude model selection policy (2026-09-02 23:00–23:20 UTC)

**Objective (GitHub Issue #100).** A TASK that names a model runs on that model; a TASK that names none gets an
automatic, explainable choice between Haiku / Sonnet / Opus; Fable stops being what runs by default and only
runs on explicit request. Path: GitHub Issue → bridge → executor, not rebuilt.

| Item | State |
|---|---|
| Branch / commit | `mythos/gh/gh-issue-100` (worktree `…/worktrees/gh/gh-issue-100`, base `dc45ff1`). Delivery is the governance relay; **not merged to main**. |
| Before | `executor.createTask` stored `model: input.model \|\| null`, no caller ever set it, and `providers/claude-code.js` only passed `--model` when it was set. So every autonomous run omitted `--model` and inherited the Claude CLI's own ambient default (the fable family). No `Model:` field existed anywhere in the Issue → control-task → executor path. |
| After | `lib/model-policy.js` + `config/model-policy.json` are the single decision point. `createTask` resolves a model for every `claude-code` task and records `model`, `model_selection_mode` (`explicit`/`auto`) and `model_selection_reason`; `buildArgs` now **always** emits `--model`. Explicit wins and is never substituted; absent is scored. |
| Auto rules | Additive integer signals: execution profile (`repo-read` 0 … `deploy` 3), task category (`investigate` 0 … `implement` 3), priority (−1/0/+1), instruction length (≥6000 +1, ≥12000 +2), complexity terms (+1 each, cap +3), simplicity terms (−1 each, cap −2), ≥6 constraints +1, ≥3 required tests +1. score ≤1 → **haiku**, ≥7 → **opus**, else **sonnet**. Every contributing signal is in the reason string, the task record, the `model_selected` event and the GitHub REPORT. Terms are plain substrings chosen not to occur in the bridge's own instruction boilerplate — a test pins that, so GitHub tasks are not pushed up a tier by their own template. |
| Fable | Every fable catalog entry is `auto_selectable: false`, and the three auto tiers are validated to name auto-selectable entries only. A test sweeps 648 signal combinations (including an instruction that asks for fable in prose) and none reaches it. |
| `Model: Fable 5.1` | **Refused, by decision.** The installed Claude CLI (2.1.251) has no such model — its catalog offers `claude-fable-5` only (`claude-fable-5-1` does not exist in the binary). Substituting Fable 5 would violate "never replace a named model", so the catalog carries `fable-5.1` as `enabled: false` with the reason, and the request is rejected at intake with that message. **Owner decision needed:** flip `enabled` to `true` in `config/model-policy.json` (no code change) once a CLI that accepts `claude-fable-5-1` is installed. |
| Security | A task/Issue can only *select a catalog key*; it can never supply a model string. Every catalog `model` is re-validated against `/^[a-z0-9][a-z0-9._-]{1,63}$/`, so no value reaching argv can carry whitespace or look like another CLI flag. `fallback_model` passes the same allow-list. Model choice grants no authority: provider, execution profile, working directory, tools, MCP capabilities and credentials remain server-side. No Resource Guard change was needed. |
| Fail-safe | An unreadable or invalid `config/model-policy.json` falls back to a built-in policy (logged on stderr) instead of disabling the layer — "no policy" would mean "no `--model`", i.e. the fable default returning. |

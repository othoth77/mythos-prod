# Mythos — Development Acceleration Architecture (DEVX-0)

**Stage:** DEVX-0 — Development Acceleration MVP
**Purpose:** Define the minimum tooling layer that lets a future Mythos stage begin from a short owner instruction instead of a long prompt, by deriving execution context from GitHub/Git evidence rather than from repeated rules.

---

## 1. Problem

Every prior stage in this repository (MPI-0, MPI-0-FINALIZATION, RES-0, and the ones before them) required the owner to write out, in full, the exact rules that already exist in this repository: preflight discipline, scope control, test strategy, risk classification, documentation requirements, stop conditions. Those rules do not change between stages — only the stage identity does.

DEVX-0 turns that repeated text into data the tooling can read.

## 2. Non-goals

DEVX-0 is developer tooling and repository orchestration only. It does **not**:

- implement any product runtime,
- touch a database,
- deploy anything,
- talk to any external provider except `git` and, optionally, `gh` (GitHub's own CLI),
- decide policy — every rule it applies already exists in `AGENTS.md`, `docs/AUTOMATION_APPROVAL_MATRIX.md`, or the existing Agent Skills; DEVX-0 only makes those rules machine-checkable.

## 3. Components

| Component | File | Purpose |
|---|---|---|
| Current Context Snapshot | `projects/meta/current-context.json` | One small file a future agent reads before scanning many documents. Regenerated by `node scripts/mythos-stage.js context`. |
| Known Baseline Registry | `projects/meta/known-baselines.json` | Independently verified pre-existing test failures (e.g. Stage 3D's 104/110), so a new failure is never silently treated as a baseline. |
| Test Impact Map | `projects/meta/test-impact-map.json` | Changed-file path prefix → track → minimum targeted tests → risk lane. Unknown paths fall back to the full suite, never to silence. |
| Development Lanes | `projects/meta/development-lanes.json` | FAST / STANDARD / HIGH_RISK classification. HIGH_RISK can never silently downgrade itself. |
| Stage Templates | `projects/meta/stage-templates.json` | Reusable entry/closure checklists by stage type (DOCUMENTATION, RUNTIME, INFRASTRUCTURE, CONNECTOR, DATABASE, SECURITY, RESEARCH). |
| Stage Runner | `scripts/mythos-stage.js` | The CLI that reads all of the above plus the existing `projects/meta/project-ledger.json` and produces a compact Stage Context. |

## 4. Relationship to existing MPI-0-FINALIZATION project intelligence

DEVX-0 **reuses** `scripts/project-intelligence.js` for ledger/statistics/registry/history validation — it shells out to it rather than re-implementing any of its checks. `projects/meta/current-context.json` reads `projects/meta/project-ledger.json`, `projects/meta/project-statistics.json`, `docs/PROJECT_STATUS.md`, and `projects/personal-intelligence/config/agent-skills-registry.json` as its sources of truth; it does not duplicate their content, only surfaces a compact derived view.

## 5. Data flow

```
git/GitHub state
      │
      ▼
projects/meta/project-ledger.json  (existing, MPI-0-FINALIZATION)
      │
      ▼
scripts/mythos-stage.js  ── reads ──▶  known-baselines.json
      │                                test-impact-map.json
      │                                development-lanes.json
      │                                stage-templates.json
      │                                agent-skills-registry.json (existing)
      ▼
Stage Context (compact JSON)
      │
      ▼
owner's short instruction resolves to a full execution plan
```

## 6. Security

- No credential is ever read, stored, or printed by any DEVX-0 file or command.
- `scripts/mythos-stage.js`'s `detectGh()` boundary returns only booleans (`installed`, `authenticated`) — it never captures or logs `gh auth status`'s token output.
- `close --apply` refuses to run for the HIGH_RISK lane (`HIGH_RISK_POLICY_VIOLATION`) — see `projects/meta/development-lanes.json`.
- Existing Mythos Automation LEVEL_3 approval boundaries (`docs/AUTOMATION_APPROVAL_MATRIX.md`) remain authoritative wherever they overlap with a development lane classification.

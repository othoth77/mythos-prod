## Roles (auth.js, owned by the integrator)
`ROLES = ['viewer','agent','manager','admin','owner']`, rank in that order. Legacy `operator` (users file) maps to
`manager`. Route `role` values: `false` (public) | `'any'` | `'agent'` | `'manager'` | `'admin'` | `'owner'`.
`'operator'` remains accepted as an alias of `'agent'`. Project access: owner/admin see every project; other
users see only `wp_user_projects` rows (empty = nothing). `api.projectFrom()` enforces it (404 for a project the
user cannot see). `req.session = { id, username, role, projects: [ids] | null(all) }`.
Protected (admin+): WhatsApp credentials/numbers/accounts writes, Meta/MCP config, AI agent config,
integrations, automations, users (owner). Writes on conversations/contacts/tags/notes/handoff: agent+.

## Route modules
`reference/api.js` keeps the existing routes and concatenates `require('./routes/whatsapp')`,
`require('./routes/ai')`, `require('./routes/platform')` (each exports an ARRAY of route objects
`{ method, path: RegExp, role, handler(req,res,ctx), stream?, csrf? }`). Handlers receive `ctx.params` (regex
match), `ctx.body`, `ctx.status(n)`; `req.session`; project resolution via `require('../api-util').projectFrom(req, {project: id})`
(returns `{ project, wpPool }` and enforces access) and `require('../api-util').q(req)` for the query string.
Every mutation calls `audit.record(db.wp(), { actor, role, action, resource, record_id, project_id, next, request_id: req.requestId, client: req.socket.remoteAddress })`.
Audit ACTIONS (audit.js, extended by the integrator): create update delete login login_failed logout status
setting upsert simulate send handoff route run sync test execute check import.

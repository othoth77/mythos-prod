# mythos-doc-sync

## What this skill does

After an implementation is validated, committed, and pushed, at **stage completion**:
- updates `docs/AI_HANDOVER.md` with objective, starting/final HEAD, implementation commit, files changed, validation results, and the exact next stage — in a separate commit from the implementation, per repository convention,
- updates `docs/ROADMAP.md` status for the stage that actually completed, without altering unrelated stage history,
- updates `docs/CHANGELOG.md` (populated as of MPI-0-FINALIZATION — see `docs/CHANGELOG.md`) and `docs/PROJECT_STATE.md` where the stage is significant enough to warrant it,
- avoids self-referential "final commit" hashes (a commit can never correctly describe its own future hash) — see the pattern already established across this repository's INF-CF-* stage handovers.

**Never marks a future or unstarted stage as complete.**

**Does not own the daily historical ledger.** `docs/history/DAILY_HISTORY.md` is triggered per verified development day, not per completed stage — that is `mythos-project-history`'s distinct responsibility (see `docs/SKILLS_EVOLUTION.md` §4 for why these are not the same trigger).

**Does not own DEVX-0's metadata regeneration either.** `projects/meta/current-context.json` is regenerated by `node scripts/mythos-stage.js context`, not authored by this skill; this skill's own targets remain `docs/AI_HANDOVER.md`, `docs/ROADMAP.md`, `docs/CHANGELOG.md`, and `docs/PROJECT_STATE.md`. Reuse `scripts/project-intelligence.js` for ledger/statistics/registry/history validation — never re-implement its checks here.

## Governing documents

`AGENTS.md` §18 (Documentation requirements), `docs/AI_HANDOVER.md` (existing entries as style precedent), `docs/DEVELOPMENT_WORKFLOW.md`.
